# Benchmark measurement and workload review — 2026-09-12

Issue: hostvaultio/platform platform-4kur.1.

Correctness review covers the PR against `origin/main`, including workload qualification. Paper numeric window labels must not enter
measurements; malformed responses cannot synthesize values, and each metric has
its own sample count. A maximum is never labelled a percentile. Missing timing
at any step now prevents a positive headline instead of silently skipping it.

The CLI records population and positions over the measured interval, updates
final population after the hold, stops at invalid workload, retains evidence and
returns status 2. Boundary observations, coverage gaps, disconnects, stalled
intervals, oscillation, absent trajectories and legacy records have regression
coverage. Live acceptance results are recorded separately in platform PR 790. A pathfinder
candidate failed live qualification and is excluded from this release.

Security review: workload observation reads client positions without introducing
new server commands, credentials or a remote control interface. No navigation
dependency is added. CI installs locked dependencies with lifecycle scripts disabled.
RCON credentials remain private input and are redacted from JSON and dry runs.
Live tests use a private internal Docker network without published ports,
resource limits and disposable worlds. Retained game data is not modified.

Limits: observed displacement is a minimum workload check, not proof of realistic
player activity, spatial separation or node density. RCON windows overlap and
are not individual tick samples. The load generator's own utilization must be
considered in capacity conclusions. Actual navigation still requires live
qualification for each terrain/protocol combination.
